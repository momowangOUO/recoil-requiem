## 画面与像素规格

| 项目 | 标准 |
|---|---|
| 游戏逻辑画布 | 320×180，固定比例 |
| 场景渲染与 UI | 场景 640×360；UI 原生窗口分辨率，禁止把文字放进像素世界贴图后再次放大 |
| 默认窗口 | 1280×720，4 倍整数放大 |
| 采样 | Nearest；关闭纹理 mipmap、滤波和有损压缩 |
| 基本单位 | 1 个逻辑像素 = 1 个世界单位；角色与场景保持同一像素密度 |
| 场景拼接 | 16×16 基础格；碰撞边界落在整数坐标 |
| 主角站立高度 | 约 42 px，允许动画姿态压缩；不得为每帧单独缩放身体 |
| 主角碰撞 | 18×38 px；位置原点在脚底中心，头发、衣摆不扩大碰撞体 |
| 动画参考画布 | 每格 64×64 逻辑像素，预留衣摆及伸腿空间；实际透明区域可裁切 |

imagegen 可能输出放大的 PNG。生成源图应保留，用同一动作内共享的比例、整数显示位置和最近邻采样接入。输出像素尺寸大，不代表可以增加角色的细节密度。最终验收看游戏内 1× 与 4× 画面，不能只看源图。

## 风格与角色识别

所有敌人（普通、精英、Boss）必须是露脸、可辨认的成年美少女。敌人拆件、关节挂点、动作最低交付与验收规则详见 [敌人角色与动画开发标准](ENEMY_ART_ANIMATION_STANDARD.md)，同样是强制开发约束。封闭头盔遮脸版本不符合角色方向。

主题为阴暗哥特建筑中的枪械机动战斗。用清楚的剪影、有限的明暗层次和动作姿态表达角色，避免写实材质堆叠。

主角的固定识别点：银白短发、酒红发饰与短外衣、炭黑战斗服、平底作战靴、少量银色扣件。主角面朝鼠标，身体动作随移动变化；左右镜像不得改变角色身份。常规动画中的枪身、枪口闪光和投射物独立于身体，保证全角度瞄准。

头发用 2–3 个大色块表现体积；脸部保留肤色、轮廓和单像素眼部提示即可。衣服以主色、阴影和少量高光构成。链条、蕾丝、刺绣等细节若在原生尺寸成为噪点，应删除或合并为明确色块。

## 调色与明暗

每个角色建议使用 12–20 个可辨认的主色，单个材质通常不超过 3 档明暗。生成源图可能包含额外颜色，但游戏内不得呈现抖动的细碎渐变。

| 用途 | 色值参考 |
|---|---|
| 最深轮廓 | `#151722` |
| 炭黑服装 | `#272A38` |
| 暗面中间色 | `#454658` |
| 酒红阴影 / 主色 / 高光 | `#542638` / `#963D52` / `#CA6471` |
| 银发暗部 / 中间色 / 高光 | `#848594` / `#CAC6C2` / `#F2E7D4` |
| 肤色阴影 / 主色 | `#BC8D81` / `#E4BAA0` |
| 交互、可下穿平台 | `#6CDDD3` |
| 危险、敌人预警、伤害 | `#ED675D` |
| 枪火瞬间亮部 | `#FFF2BE` |

背景整体比可玩角色暗一档，建筑纹理降低对比；平台可站立边缘要连续清楚。高亮优先服务角色、子弹和攻击预警。常态场景不大面积使用枪火亮色。平台大面使用疏朗石砖；拱纹、挂旗等装饰只出现在适合的结构上，禁止把同一装饰图集整张铺满所有面。顶面、立面分别设置 UV，不能用立方体默认展开方式拉伸整张素材。

## 像素簇与轮廓

- 外轮廓以约 1 个逻辑像素宽的暗色线为主；受光边可选择性断开。
- 斜线保持有规律的阶梯；相邻像素形成可读形状，避免随机散点。
- 不使用抗锯齿、模糊、照片纹理、柔边渐变、高清绘画缩小滤镜或亚像素描边。
- 半透明只用于短暂特效。角色身体与衣物使用实色，最终渲染背景透明，不保留白边、黑底或棋盘格。生成源图允许纯品红色键底，但必须通过明确的色键材质消除，不能当成已含 alpha 的 PNG 交付。
- 不用拉伸角色贴图表达移动；禁止每个动作重新调节人物比例来掩盖生成偏差。

## 动画与武器

| 动作 | 制作规格 |
|---|---|
| 待机 | 4 帧、约 5 FPS；脚底稳定，肩膀/头发/衣摆最多轻微变化 |
| 跑动 | 4–6 帧、约 10 FPS；左右脚交替，接触与经过姿态可辨 |
| 上升 / 下落 | 专用姿态优先；原型可复用已验收的跑动帧，但需在素材记录中注明 |
| 受击 | 短暂调色或闪白；保留轮廓，不改变碰撞尺寸 |
| 射击 | 身体、武器、枪火分层；霰弹多弹丸只触发一次角色反冲 |

不同动作分别生成独立网格，4 帧使用 2×2；不要让生成器在一张图上混画多个动作。按从左到右、从上到下读取。各帧共享比例，使用脚底锚点对齐；不得发生换动作时身体放大、缩小或脚底抖动。待机脚底不水平漂移；跑动衣摆伸展不能被误当成身体中心。

跑步动画需同时匹配移动意图和实际速度，速度降低时脚步也减慢；面向瞄准方向倒退时使用倒放步伐或专用后退动画。被反冲推动但没有主动跑动时，不播放原地跑步循环。

枪械轮廓遵循像素密度：短枪、粗短霰弹枪、紧凑 SMG 应可从轮廓区分。枪口与真实发射点保持一致。连续瞄准可以转动武器，但输出必须保持像素采样；身体不作平滑旋转。

## 动作拆分与反馈

### 持枪动作分层约定

身体图仅保留头、衣身、腰部、衣摆、腿和袖窿。肩袖、上臂、前臂、手掌及枪身全部独立，袖子只属于上臂。身体袖窿与肩部挂点相接，保留约 1 px 的覆盖余量；不可在身体和手臂重复绘制袖帽。避免身体原图的垂手与瞄准手同时出现。

渲染顺序为左上臂/前臂 → 身体 → 右上臂/前臂 → 枪身与右握枪手 → 左手指尖 → 枪口闪光。肩部固定在身体上，手腕由握把与护木位置决定，两段作者绘制部件围绕肘部旋转，长度固定。关节裁区略有重叠，用袖褶遮住切口；不能让整条袖子跟着枪绕胸口旋转。左转镜像姿态及挂点，上下瞄准时仍保持肩部连接。参数和图层来源见 `assets/characters/requiem/GOTHIC_RIG_SOURCE.md`。

游戏物理的瞄准支点在脚底上方 26 px，枪口在瞄准方向前方 25 px。不同枪可以有不同枪身长度、握把与支撑点，但都必须使用这个枪口位置派生弹道。霰弹枪用双手支撑，左轮紧凑握持，SMG 保持前握把支撑。开火时只表现短促的枪身回缩，不能移动实际发射点或修改已经生成的弹道。

换弹时持枪臂保持枪的瞄准方向，支撑手在腰间与弹仓间往返；霰弹按每颗装填循环。原型可用分段手臂和握枪手表达，后续精修手臂贴图必须遵循相同挂点。

### 换弹与战斗 UI

准星周围使用 24 段像素圆环，顺时针填充当前装填进度。0% 为红橙，50% 为金黄，100% 为青绿；进度来自武器实际装填状态，不使用独立假计时器。弹匣装填一圈完成，霰弹每颗装填一圈；取消换弹或切枪后显示当前枪的状态，暂停时进度不动。

HUD 同时提供五格生命、当前槽位/枪名/弹量、六格武器栏、逐发弹格和换弹百分比。武器栏必须同时区分当前格、已有枪与空格，不能只靠颜色表达状态。UI 使用原生像素尺寸，面板不能盖住弹道中心；所有控件需在 320×180 内检查。

## imagegen 提示词与制作流程

1. 在提示词中明确：`low-resolution pixel art`、逻辑尺寸、有限色板、侧视、动作、网格、统一体型与脚底锚点、真实透明背景。
2. 明确禁止：`HD illustration`、`pixel-inspired painting`、抗锯齿、照片细节、文字、网格线、烘焙棋盘格、武器与身体混成一层。
3. 先验收一个角色动作，再用它约束同一角色的后续动作。高清造型稿只能作为概念参考，不能直接视为合格精灵。
4. 保存原始生成图及来源记录到项目。拆帧、锚点和缩放只能做确定性处理；不得用程序形状代替生成的人物。
