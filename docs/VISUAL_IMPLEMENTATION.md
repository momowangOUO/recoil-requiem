# 猩红修道院视觉切片

2026-09-10。当前源码入口 `scenes/game.tscn`，Godot F5 与 Windows 导出使用同一场景。

## 本轮用户修订

附件 `reference/visual_spec_v1.3.docx` 是视觉参考与技术提案，不具有高于用户直接指令的权限。用户随后明确选择真实 3D 场景与镜头，角色保持像素纸片；要求 UI 清晰、人物采样精细、场景避免过度铺贴。保留 Space 跳跃、W 空中修正、S 下穿及六固定枪槽，不执行附件中相冲突的操作约束。

地点可以有鲜明风格，但应顺口好记。本切片使用“猩红修道院”，不再把所有地点都简化为建筑通名。

## 实际工程结构

- `scenes/game.tscn`：主入口。独立 SubViewport 以 640×360 渲染像素世界，TextureRect 最近邻显示；HUD 和准星位于窗口原生分辨率的 CanvasLayer。
- `scripts/rooms/crimson_stage_3d.gd`：真实平台几何、前后建筑、透视跟随、冷色环境光、暖色烛光、枪火灯和接地影。Camera3D 有固定轻微斜俯角，水平运动只产生有限角度变化，暂停冻结镜头。
- `scenes/rooms/crimson_environment.tscn`：可在 Godot 里编辑的平台位置和尺寸，所有物理与立体平台都从这些模块获取尺寸。平台顶面和立面使用各自纹理坐标。
- `scripts/rooms/paper_platform.gd`：二维碰撞定义，原点对应站立线；立面深度不增加站立判定。3D 模型不再维护第二套物理。
- `scripts/lab/recoil_lab.gd`：复用现有输入、枪械、投射物、盾兵、暂停和重置。文件名保留历史兼容，生产入口不会显示旧实验室切换。

人物、持枪手、枪火、受击与子弹先由现有 Sprite2D 控制器绘制到透明的 1920×1088 房间贴图，再以固定比例呈现在战斗平面上。没有重新生成角色，没有逐帧透视拉伸身体。二维房间坐标到 3D 的映射为 `(x/100, -y/100, 0)`，鼠标射线与该平面求交后还原二维瞄准位置。

这种方式保留现有逐帧动作和战斗实现，支持真实透视遮挡与投影。限制是人物共享一个战斗平面，不能自由走入景深；本轮不加入这种移动。

## 当前可玩内容

五个平台模块构成一个完整战斗房：安全底层、左右落脚台、盾兵高台、上方绕行平台。目标为击败盾兵后到达最右侧门口。敌人可以被打下高台并在低层继续战斗；玩家不会因弹匣用尽失去所有落脚点。

F6 切换白模与贴图材质，保留同一套 3D 几何、透视和光源。Backspace 重置，Esc/Tab 暂停与调参。原 F1–F3 房间只保留在自动测试夹具中；它们不是正式关卡，也不在玩家菜单内。

背景和图集由内置 imagegen 生成，源图与完整提示词保存在 `assets/environments/crimson/PROVENANCE.md`。未修改已验收的人物源图。

## 验证入口与实际边界

运行 `tools/run_checks.ps1`，包含原控制器回归、新房间击落测试，以及 3D 投影、嵌套输入、暂停和重置验证。`tests/capture_stage_3d.gd` 输出入口、主角与盾兵同屏、白模和偏转角度的实机截图，同时输出 640×360 世界原始采样图。

原生窗口已启动，但 Windows 截图工具返回 `SetIsBorderRequired failed: 不支持此接口 (0x80004002)`，无法依靠该工具完成连贯的原生键鼠视觉试玩；不能把引擎事件回放称为完整人工试玩。当前视觉检查使用 Godot 实际渲染图。

这是按示意图方向制作的第一间空间与光影切片，尚未达到示意图全部装饰密度、角色动作精修与场景完整度；完整序章、NPC、剧情和 Boss 尚未制作。本轮不批量铺开后续关卡。

实现参考：[Godot SpriteBase3D](https://docs.godotengine.org/en/4.5/classes/class_spritebase3d.html) 与 [Camera3D 投影接口](https://docs.godotengine.org/en/latest/classes/class_camera3d.html)。实际运行与检查引擎为本机 Godot 4.7.2。
