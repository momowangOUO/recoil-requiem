# 先图后施工的游戏美术

把生成图当作有对应关系的施工依据。漂亮原图、素材存在、自动测试通过，分别不能证明实机达到了视觉目标。

## 开始前

先读项目美术规则、相关已采用原图和当前实机截图，确定本次一个可完成的切片。保留已有玩法、坐标、镜头、文字语言和用户已选风格；不要把某个项目的哥特题材、配色或纸板形式推广成所有项目的规范。

记录两类约束：不可变的玩法／状态／文字安全区；可以调整的构图／材质／层次。地图先取得真实路径及区域数据。已有合格示意图可以直接用，不为履行流程重复生成。

## 制作顺序

1. **完整画面稿。** 新视觉先用可用图像生成工具制作完整画面。按环境读取实际 `imagegen` 技能，不虚报工具或模型版本；工具不可用时明确说明，不能用程序图冒充生成图。对交互、布局与真实地形有约束时提供它们作为参考，标清每张图的用途。生成图中的虚构通路不能自动成为玩法。
2. **图与施工的对应。** 记录原图区域、运行节点／资源、世界矩形或UI锚点、层次、缩放规则、碰撞与动态状态。把原图存在而运行版没有的主体列为差异，不能只取底色就说照图完成。使用 [施工记录](references/construction-record.md) 中与当前切片相关的字段即可。
3. **分层与素材。** 先在完整画面上验证，再提取运行素材。窗、墙、遮挡、角色、机关等按实际运动和透视需要分开；UI装饰与动态文字分开。检查生成图实际尺寸、透明度、轮廓和留白，再确定裁区；提示词要求等分图集不代表产物真的等分。只伸缩明确设计为可伸缩的区域，不拉长整幅装饰画。
4. **一个实机切片。** 接入真实运行场景，保留玩法数据作为通行、探索、门锁与进度的权威。先证明一个区域／一个界面成立，再扩展同类内容。对运行规则与原图的冲突，修订对应图或记录具体转换，不能靠透明度隐藏矛盾。
5. **对照与动态验收。** 把同视角原图和实机截图放在一起检查主体占比、轮廓、材质密度、图层、文字与可读性。再连续测试缩放、横移、跳跃／高度变化、窗口尺寸，以及未探索／已探索、锁门／开门等状态。逐帧重置的截图不能代替连续动作。看到偏差就修，再截图。

## 交付边界

保留采用的原图、提示词、裁区／配准、运行资源和实际渲染证据。源图与开发资料按项目打包规则排除。明确区分自动回放、人工审图和真人操作；报告仍有的视觉差异，不把局部完成称作整游戏完成。

提交、发布、安装与删除仍须来自用户授权；本技能不增加权限。流程跑通后只提炼跨项目可复用的判断，项目专名、数值和未完成项留在项目资料中。
