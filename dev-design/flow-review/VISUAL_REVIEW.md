## 素材与调整

使用内置 imagegen，用户称 image2；工具未开放具体模型版本选择，因此不声称锁定了 image2 或 image2.5。每个节点分别生成，不拿一张图反复裁切充数。采用的完整原图保存在 images/01.png 至 12.png；提示词见 prompts.json，局部修订提示词、来源路径、尺寸与文件哈希见 SOURCE_MANIFEST.json。

第一批偏向建筑插画，交谈人物偏大，已退出交付。用户补充要求后，改用实际游戏的中距离截图作为首要参考，保留道路顶面、地基、窗墙分层和人物纸片感。随后针对 NPC 过高、主角占比不一致做局部重绘。图 02 删除误生成的门口人物；图 12 删除不符合角色标准的额外坐姿人物，只保留外庭回访。

参考实机保存为 references/actual-camera-5.2.png 与 actual-camera-7.2.png，分别来自现有 image_arch_garden 与 architecture_grounding_gallery 截图。镜头数值核对 scripts/rooms/crimson_stage_3d.gd 和 tests/capture_image_architecture.gd。5.2 距离下主角约占画高 17–18%，7.2 距离下约 12–13%；三枪近远范围保持运行数据。

12 张图均作为场景与流程示意采用，不提取人物回游戏。图 06、07 使用较近的画面占比，图内 HUD 用霰弹枪；其他画面以左轮中远视野为意图。生成结果仍是手工审看的构图参考，不能伪称由 Godot 投影精确重建。施工时必须在相同镜头参数下用现有角色重新对照，不能调整角色缩放去适配绘图误差。

## 再生成文档

使用 Python 运行 build_document.py，从 beats.json、DESIGN.md 和独立文案草稿生成 flow.html。使用浏览器打开网页后可打印；需要一致的 PDF 导出时，在已打开本页的 Playwright CLI 会话运行 export_pdf.js。

网页依赖项目已有 UI 和字体，单独发送时优先使用 PDF；可在仓库原路径完整浏览 HTML。源图目录不依赖 Codex 临时生成位置。dev-design 与 game-text 已在现有 export_presets.cfg 的排除范围内。
