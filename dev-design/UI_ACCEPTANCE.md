## 2026-09-20 M 地图连接与可读性修订

用户指出上一版把建筑图标、平台带和编号叠在一起，难以判断真实连接。本轮保留已生成的羊皮纸、标记和建筑素材，但把建筑图标移到选中地点的右侧预览。主图仅用实际施工的道路、楼梯、门和检查点构成路径；重叠的 Section 不再把同一道路描两次。五段位于 Section 矩形外的真实过渡构件明确补入可见规则，因此全探索时 56 段均完整出现，局部探索时仍不提前显示未到达一侧。区域数字固定采用 mon_01–mon_16，并锚在真实行走层；选中礼堂会居中其道路，不会居中高大区域的空白矩形。

货运捷径使用实际游戏中两个操作点，以同一字母配对；只有已开通且两端已探索时才绘点线。实体门的锁闭图标使用门体与道路的交点，不再放在两个区域中心之间。未知入口由可见道路在探索边界处结束的位置决定，未画猜测走廊。图例短句先写入 `game-text/map-ui-navigation-v3-review.md`，再按原文接入。

`tests/test_image_map_ui.gd -- --campaign-test` 在实际 GPU 场景完成 940 项检查、0 失败，覆盖960／1280／1920和宽屏请求、局部／全图、锁门／开门、56 段完整性、捷径端点、编号锚点、聚焦、平移和缩放。实际截图包括 `artifacts/image_map_ui_1280_3_locked.png`、`image_map_ui_1280_full.png`、`image_map_ui_1280_selected_gatehouse.png` 与 `image_map_ui_1280_selected_chapel.png`；960 版本的侧栏文字已逐张复看，按钮保持单行。宽屏请求仍受本机桌面分辨率夹到1920×1080，不能当成原生2560像素截图。

完整回归 `tools/run_checks.ps1` 见 `artifacts/map-navigation-full-checks.log`，含地图 headless 923 项与其余全部现有检查，均无失败；另一次实际窗口 UI 验收为116项通过。唯一 Windows EXE 已覆盖，内嵌资源检查0失败，GPU启动180帧退出码0。运行包为 Godot 4.7.2 调试模板导出，因为本机没有 release 模板；`builds/windows` 中仍只有 `RecoilRequiem.exe`，文件大小140469984 bytes，SHA-256 `4774bc92647d5d6515a8c214e5da217236619843da216b15f085a03be545b1d8`。这次是脚本与截图验收，没有新增真人连续通关记录。

## 用户反馈后的修订
用户否定了首版观感，因此此前84项功能检查不作为视觉达标依据。已移除正文后方的拉伸花纹和任务整图底板，改用干净的深红灰底与细边；面板安全边距36，按钮补禁用态，焦点边框不覆盖底色。新增4项结构回归，实际主场景88项通过，三个尺寸截图已重拍。EXE重新导出并启动120帧，无脚本错误。美观程度仍需用户实机评价，不宣称自动测试证明美观。
