# 任务 UI 实机验收

2026-09-14。依据 `ART_AND_UI.md` 与 `docs/ART_STANDARD.md`。本轮保留白发 v5 主角与既有左下战斗 HUD，不生成新美术。

验证入口：`tests/capture_ui_acceptance.gd -- --campaign-test`，实际实例化 `scenes/game.tscn`，Godot 4.7.2 / OpenGL / NVIDIA RTX 3070。结果为 **84 项检查通过**，包括三种尺寸重复的房间名、布局和输入检查。此前 `tests/capture_campaign.gd` 的真实 E 键已成功打开玛拉对话。本轮实际 J 键打开日志，鼠标选择支线、地图条目和滚动后的对话选项均通过。

| 标准 | 实测结果 |
|---|---|
| 1280×720、1920×1080、960×540 | 三种窗口均完成真实场景截图；地图和长对话面板未越过 1280×720 设计画布 |
| 任务界面原生文字 | 正文/按钮最低分别为 24、36、24 实际像素；960 窗口主动放大字体，不再缩成 18px |
| 左下生命、枪和弹量 | 原有 HUD 保留，地图/对话左边界给其留出位置；未添加黑色 HUD 背板 |
| 射击比例环 | 未射击时隐藏；成功射击后出现，0.35 秒窗口结束后隐藏 |
| 换弹比例环 | 与真实 `WeaponRuntime.progress()` 相等；暂停冻结，取消消失；霰弹枪装入第一发后显示下一发的当前进度 |
| 一个主目标、一条自选支线 | 从真实日志按钮选中维修记录后，追踪只显示该支线；未同时列出工具任务 |
| 长对白与选项 | 用已批准维修原文重复构成压力样本；三种尺寸均可滚动到底并点击选项，暂停期间信号正确 |
| 16 空间地图 | 所有已探索空间有编号及可滚动完整名称按钮；点击条目高亮对应空间；没有名称被压成残缺字串 |
| 探索边界 | 仅一个空间已探索时，界面只有该空间的名称按钮；其余 15 个名称不进入 UI，只保留邻接入口标记 |
| 临时面板 | 地图和日志打开期间暂隐右上追踪，关闭后恢复，避免半块追踪面板从地图后露出 |
| 追踪语义 | 第五步使用“突破赛琳的封锁”，不再拿赛琳的警告台词当玩家目标；独立稿与实际 JSON 已核对 |

本轮修复了地图名称截断、宽地图把楼层压得过扁、房间填色遮掉门锁连线、960 字体过小、支线末字孤立换行，以及右上底板不随文字高度增长的问题。地图采用空间连接示意图，横纵轴独立适配；它保留上下层与连接关系，不用来测量实际行走距离。编号与右侧完整名称对应，不显示未探索空间详情。

- `ui_acceptance_world_without_ui_1280.png`：隐藏任务 UI 和战斗 HUD 后的世界画面，用于定位下方深色区域。

限制：完整地图与长对话使用显式测试状态，未把它们称为玩家自然探索完 16 个空间的试玩。自动测试证明输入、状态和布局，不代替长时间真人体验。最终复查将枪名从设计字号14放大到20（960窗口为15实际像素），主要弹量保持清晰大字；修改后84项实机检查与16项战斗HUD检查再次通过。画面下方连续深色区域在隐藏全部 UI 后仍存在，采样点颜色完全相同，来源是世界渲染背景。任务素材自身是局部酒红底和旧银边，没有额外黑边或铺底。下方块状深色的观感本轮尚未改善，后续仍需补足镜头可见范围内的场景层次；不能因来源不是 UI 就把整个画面问题视为已解决。

## 用户反馈后的修订
用户否定了首版观感，因此此前84项功能检查不作为视觉达标依据。已移除正文后方的拉伸花纹和任务整图底板，改用干净的深红灰底与细边；面板安全边距36，按钮补禁用态，焦点边框不覆盖底色。新增4项结构回归，实际主场景88项通过，三个尺寸截图已重拍。EXE重新导出并启动120帧，无脚本错误。美观程度仍需用户实机评价，不宣称自动测试证明美观。
