## 建筑与动线

图从左至右是运输站与门楼、吊车装卸庭、钟楼庭院、装车花园和运输礼堂。建筑的高度、跨度和围合程度各不相同。主要地面随庭院标高升降；下层只在货道、泵房与回访隧道出现，不贯穿每一栋建筑。上层廊桥用于侧翼观察和反冲切入，不成为另一条从头跑到尾的高速路。

construction.svg是依据生成图绘制的施工剖面；construction.html将两者并排，方便核对。实线表示从源图提取的路面或楼梯，紫色虚线表示源图没有画清、施工必须补建的连接。不能把补建位置说成已经由imagegen画好。

尺寸使用设计换算：源图坐标(x,y)对应逻辑坐标(8x,1120+8(y-430))。宽度16384px；人物仍为42px高，源图中的小人只是示意，不能按图中小人尺寸放大主角。图示总览不代表正常游戏镜头；分区展开后必须以实际角色尺度检查净空与景物密度。

现有16个空间ID与剧情角色保留，但不再用16个等价长方形建房。ID在下表对应建筑内部的功能区域；最终具体边界须从新几何生成，旧坐标不照搬。

## 独立可步行楼梯

楼梯采用独立场景组件，包含StairVisual、RampCollision、LandingBottom、LandingTop、RearRail和Support。地图只放组件实例并设起点、终点、梯宽和材质，不再摆30个格栅冒充楼梯。

每级视觉踏步建议12px进深、6px升高；实际碰撞是连续封闭梯身的斜面，建议坡比1:2，约26.6度，最大35度。楼梯上下端各保留至少96px水平接段，折返平台至少192px。玩家只按A/D即可上下；停下不会自己溜坡；换弹可继续走。Space、V和开火都不是通行前提。

楼梯主体默认实体，不能从正下方穿过；只有明确开放的另类检修梯才能配置单向碰撞，不能把这一例外用回全部楼梯。楼梯可视踏步与坡面最大误差6px，避免鞋底明显悬空。栏杆放在玩法平面后侧，柱脚连到梯梁或落地平台。

Godot 4.7.2的CharacterBody2D已有斜面移动与贴地支持，官方说明：https://docs.godotengine.org/en/stable/classes/class_characterbody2d.html 。贴地不得吞掉跳跃或反冲向上冲量；是否启用匀速坡行在隔离夹具中量测后决定，不直接改全局手感。

## 逐件施工与防穿帮

新清单在construction.json。每个楼梯记录起止世界坐标、实际坡比、上下平台和来源图区域。基础、后墙、门洞、廊桥与支承分别建节点，不能把这一整张概念图贴成游戏背景假装完成场景。

- 门楼：完整石墙、拱洞侧壁、阳台底梁，入口楼梯附着在门楼上。阳台下可走穿堂，不能用整块碰撞墙堵死。
- 吊车庭：吊车柱落地，滑轮吊点接横梁，货箱不侵占最低112px主路净空。吊着的货物是布景，未做动态装卸时不提供交互提示。
- 钟楼：铜钟悬在横梁下；两侧石墩从基座连续上升。开放庭院下方是泵房实体墙，不能从镜头边缘看到房间背面的空壳。
- 货道与泵房：罐底有鞍座，管道末端进法兰，后墙遮住天空；每段隧道入口有真实洞壁。水仅在最底部背景，不新增淹水机制。
- 花园：棚柱连接地面；玫瑰留在花槽中，与通道隔开；栏杆在门和楼梯入口断开。
- 礼堂：前门门叶、框体、内壁和碰撞统一开闭；高窗与玻璃是退后贴片，拱肋、地面、楼梯和看台为3D。
- 前景：只在下缘放独立二维残墙和枝叶；画面边缘不得露出贴片水平底边。不得以加黑色遮罩掩盖缺地基。

## 转换边界

生成图的建筑形象已经落盘，施工图与结构清单据此提取。原图部分通路并不连通，紫色补建项必须经过实际控制器验证。楼梯隔离夹具验证可步行的技术路线，不能称为整关完成。游戏、角色美术与唯一EXE本轮尚未更新。

2026-09-15隔离验证：tests/measure_walkable_stairs.gd在Godot 4.7.2运行，4项通过。现有真实控制器走过384×192斜面，上行到顶、下行接平地、松手停驻、射击反冲脱离坡面均通过；没有更改PlayerController。日志artifacts/walkable-stair-feasibility.log。该结果证明连续梯面可行，不表示16段楼梯已经实装，也不涵盖负向镜像、敌人寻路或完整楼梯美术。
