# 任务、地图和保存接口

状态：CampaignState、MonasteryData、CampaignSession 已接入主入口；实现与验收边界见 IMPLEMENTATION.md、VALIDATION.md。人物与事件仍须在审阅后登记。

## 职责

任务定义保存稳定 ID、前置条件、目标列表、完成条件、结果事件和文本 ID，不保存当前进度。世界状态保存已发生事实；任务、门、NPC、日志和地图只读取这份状态，不各自猜测。

事件包含事件 ID、来源实体 ID 和必要数据。永久拾取、机关完成和任务奖励必须带唯一结果 ID，重复收到同一结果不再次执行。UI 的显示函数不能完成任务、发奖励或改变 NPC。

区域连接保存两端入口和可通行条件。节点 ID 不依赖它目前处于哪个场景子节点下。临时敌人活动状态留在当前遭遇里，永久死亡只用于故事明确登记的角色或首领。

## 事件与检查点

玩家调查后立即记录证据；如果先取得证据再接任务，任务根据已有事实更新。对白选项按已知条件显示，不出现提示里已写出未发现答案的选项。对话开始和结束时清除旧开火、跳跃、V 近战输入。

完成永久机关先写入状态，再由门和地图同步表现。任务中的目标更新由事件驱动，但读档时必须从存档重建出相同结果，不依靠重播旧对白。

死亡恢复检查点位置、未完成遭遇和战斗运行状态，保留证据、已完成任务、已选决定和永久捷径。每个恢复规则都写在数据里；不把场景根节点整体重建作为清空所有任务的理由。

磁盘存档写版本号、当前区域/检查点、永久事实和必要玩家状态。先写临时文件并完成校验，再替换有效存档；损坏文件不能默默触发新游戏覆盖。未确认故事事件不生成存档键。旧原型没有磁盘剧情存档，不承诺迁移不存在的历史剧情。

## 地图与加载

保留当前二维角色和物理规则，分区仅负责加载和可见合成，不重置世界坐标或镜头。地图片区的玩法几何和 3D 展示共用编辑器数据。不要把十八千像素宽的区域画进固定分辨率的一张角色贴图。

每个连接明确进入点、离开点、开放条件、物理阻挡和返程方式。还没解锁时只能显示已发现的门和可见阻碍，不揭示背后的完整秘密路线。加载边界要安排在可控的走廊或建筑连接处，不能让射击中途跨区消失的敌人免伤。

## 验收场景

- 接任务前取得证据；两条支线分别先后完成；重复收到结果事件。
- 保存时门刚打开；开门后死亡；读档后不重新生成已完成 NPC。
- 同一任务不同对白选项改变事实后，日志、门和敌人部署一致。
- 区域往返保持捷径、镜头和投射物边界行为，不留下重复节点。
- 空存档、合法存档、错误版本、截断文件分别处理，不覆盖原文件。
- UI 暂停时没有旧射击、跳跃或近战输入泄漏到恢复后的首帧。
